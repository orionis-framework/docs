<a id="column-api"></a>

The catalog contains **40 `Column` factories for 39 logical types**, including the id shortcut. Every factory is also available on `Blueprint` and returns a concrete `ColumnDefinition`; construction executes no SQL. ORM classes are imported from orionis.orm. The 35 types with a builder can translate to SQL, while four markers have no compilation support and are explicitly identified at the end.

## Reading the signatures

The first name in each factory is the SQL column name and is required, except for id(name="id"). The asterisk marks keyword only arguments. ORM constructors do not take that column name: the metaclass reads it from the declared attribute. Every definition supports [column modifiers](/en/database/schema-modifiers). Initial state is NOT NULL with no index, uniqueness, autoincrement, or default; id enables both a primary key and generation.

DDL fragments were checked by compiling the example definitions using the installed SQLite, MySQL, PostgreSQL, SQL Server, and Oracle dialects. **Compilation does not certify server acceptance**: strict types such as CLOB, BINARY, NCHAR, and TIMESTAMP retain backend specific meanings. Redshift requires its extra; see [drivers](/en/database/dialects-and-production) for its restrictions.

SQL fragments below come from a separate probe declaration: sample, with length=80 for `String`/`Unicode`/VARCHAR/NVARCHAR, 2 for CHAR/NCHAR, 16 for BINARY, 64 for VARBINARY, and precision=12/scale=2 for decimals. Remaining options use defaults, including timezone=False. Usage examples may choose different values.

## Shared parameters

| Parameter | Effect |
|---|---|
| length | Declared text or binary length; does not validate HTTP payloads. None leaves backend defaults. |
| collation | `Column` collation; must exist on the selected database. |
| precision / scale | Total and fractional digits in `Numeric`/`StrictDecimal`. `Float` precision has dialect specific semantics. |
| asdecimal | Requests Decimal rather than float for numeric results; does not turn approximate storage into exact storage. |
| decimal_return_scale | Scale used when converting approximate results to Decimal. |
| timezone | Requests timezone support; does not provide universal timezone conversion. |
| create_constraint / constraint_name | Creation and naming of emulated boolean/enum CHECK constraints. Constructors use name. |
| native_enum / validate_strings | Native ENUM selection and string validation through its processor. |
| native / second_precision / day_precision | INTERVAL representation and precision. |
| as_uuid / native_uuid | UUID objects and native representation where available. |
| none_as_null | Distinguishes JSON null from SQL NULL for None values. |

<a id="column-id"></a>

## id: Generated identifier

```text
Column.id(name: str='id') -> BigInteger
BigInteger()
```
Use this for an automatically generated integer primary key. It is `BigInteger` with primary and autoIncrement already enabled; do not add another primaryKey. SQLite receives INTEGER to preserve ROWID. Oracle receives Identity, SQL Server receives IDENTITY, and Redshift needs its dialect and cannot automatically return the generated key.

```python
from orionis.database.schema.blueprint import Blueprint
from orionis.orm import BigInteger


table = Blueprint()
column = table.id()
model_column = BigInteger().primary().autoIncrement()
```

The factory returns `BigInteger`; the constructor returns a new instance of that type. Both inherit `ColumnDefinition`.

DDL from the probe declaration: `sqlite`: `INTEGER NOT NULL`; `mysql`: `BIGINT NOT NULL AUTO_INCREMENT`; `pgsql`: `BIGSERIAL NOT NULL`; `sqlserver`: `BIGINT NOT NULL IDENTITY`; `oracle`: `NUMBER(19) GENERATED BY DEFAULT AS IDENTITY`.

<a id="column-enum"></a>

## enum: Enumerations

```text
Column.enum(name: str, *enums: str, constraint_name: str | None=None, create_constraint: bool=False, native_enum: bool=True, length: int | None=None, validate_strings: bool=False) -> Enum
Enum(*enums: str, name: str | None=None, create_constraint: bool=False, native_enum: bool=True, length: int | None=None, validate_strings: bool=False)
```
Use for a closed set of nonempty string states. Missing or invalid members raise `ValueError`. native_enum=True requests native ENUM; give it constraint_name on PostgreSQL (name in the constructor). native_enum=False uses VARCHAR; create_constraint=True adds CHECK where applicable. validate_strings validates values through the type processor and does not create an HTTP schema.

```python
from orionis.database.schema.blueprint import Blueprint
from orionis.orm import Enum


table = Blueprint()
column = table.enum("status", "draft", "published", constraint_name="article_status", native_enum=False, create_constraint=True, validate_strings=True)
model_column = Enum("draft", "published", name="article_status", native_enum=False, create_constraint=True, validate_strings=True)
```

The factory returns `Enum`; the constructor returns a new instance of that type. Both inherit `ColumnDefinition`.

DDL from the probe declaration: `sqlite`: `VARCHAR(9) NOT NULL`; `mysql`: `ENUM('draft','published') NOT NULL`; `pgsql`: `article_status NOT NULL`; `sqlserver`: `VARCHAR(9) NOT NULL`; `oracle`: `VARCHAR(9 CHAR) NOT NULL`.

These fragments use draft/published members and the name article_status, with the default native_enum=True. The executable example above deliberately selects emulation and validation.

## Applying a complete declaration

The examples above separate construction from execution. Within a migration, the blueprint collects the same definitions and `Schema` materializes them on successful context exit.

```python
from orionis.database import Migration
from orionis.support.facades import Schema


class CreateProducts(Migration):
    async def up(self) -> None:
        async with Schema.create("products") as table:
            table.id()
            table.string("name", 120)
            table.numeric("price", 12, 2).default(0)
            table.boolean("active").default(True)
            table.timestamps()

    async def down(self) -> None:
        await Schema.drop("products")
```
