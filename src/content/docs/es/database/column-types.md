<a id="column-api"></a>

El catálogo contiene **40 factorías de `Column` para 39 tipos lógicos**, incluido el atajo id. Cada factoría también está disponible en `Blueprint` y devuelve una `ColumnDefinition` concreta; construirla no ejecuta SQL. Las clases del ORM se importan desde orionis.orm. Los 35 tipos con builder pueden traducirse a SQL, mientras que cuatro marcadores carecen de compilación; se identifican expresamente al final.

## Cómo leer las firmas

El primer name de cada factoría es el nombre SQL de columna y es obligatorio, salvo id(name="id"). El asterisco marca parámetros que solo se pasan por nombre. El constructor ORM no recibe ese nombre: la metaclase lo toma del atributo declarado. Todas las definiciones admiten los [modificadores de columna](/es/database/schema-modifiers). Sus valores iniciales son NOT NULL, sin índice, unique, autoincremento ni default; id es el atajo que activa clave primaria y generación.

Los fragmentos de DDL se comprobaron compilando las definiciones de ejemplo con los dialectos instalados de SQLite, MySQL, PostgreSQL, SQL Server y Oracle. **Compilar no certifica que un servidor acepte el tipo**: tipos estrictos como CLOB, BINARY, NCHAR o TIMESTAMP conservan particularidades del motor. Redshift necesita su extra y sus restricciones se explican en [motores](/es/database/dialects-and-production).

Los fragmentos SQL siguientes proceden de una declaración de prueba independiente: sample, con length=80 para `String`/`Unicode`/VARCHAR/NVARCHAR, 2 para CHAR/NCHAR, 16 para BINARY, 64 para VARBINARY y precision=12/scale=2 en decimales. Las opciones restantes usan defaults, incluido timezone=False. Los ejemplos de uso pueden elegir valores distintos.

## Parámetros compartidos

| Parámetro | Efecto |
|---|---|
| length | Longitud declarada de texto o binario; no valida el payload HTTP. None deja la decisión al motor. |
| collation | Intercalación de columna; debe existir en la base seleccionada. |
| precision / scale | Total de dígitos y dígitos decimales en `Numeric`/`StrictDecimal`. En `Float`, precision tiene semántica del dialecto. |
| asdecimal | Solicita Decimal frente a float en tipos numéricos; no cambia una columna aproximada en exacta. |
| decimal_return_scale | Escala usada al convertir resultados aproximados a Decimal. |
| timezone | Solicita soporte de zona del tipo; no hace conversión automática universal. |
| create_constraint / constraint_name | Creación y nombre del CHECK para boolean/enum emulados. En los constructores se usa name. |
| native_enum / validate_strings | Elegir ENUM nativo y validar strings en su procesador. |
| native / second_precision / day_precision | Representación y precisión de INTERVAL. |
| as_uuid / native_uuid | Objetos UUID y representación nativa donde exista. |
| none_as_null | Diferencia entre JSON null y SQL NULL para valores None. |

<a id="column-id"></a>

## id: Identificador generado

```text
Column.id(name: str='id') -> BigInteger
BigInteger()
```
Úsalo como clave primaria entera autogenerada. Es `BigInteger` con primary y autoIncrement ya activados; no lo combines con otra primaryKey. En SQLite se compila INTEGER para conservar ROWID. Oracle recibe Identity; SQL Server, IDENTITY; Redshift necesita su dialecto y no devuelve automáticamente la clave generada.

```python
from orionis.database.schema.blueprint import Blueprint
from orionis.orm import BigInteger


table = Blueprint()
column = table.id()
model_column = BigInteger().primary().autoIncrement()
```

La factoría devuelve `BigInteger`; el constructor devuelve una nueva instancia del mismo tipo. Ambos heredan `ColumnDefinition`.

DDL de la declaración de prueba: `sqlite`: `INTEGER NOT NULL`; `mysql`: `BIGINT NOT NULL AUTO_INCREMENT`; `pgsql`: `BIGSERIAL NOT NULL`; `sqlserver`: `BIGINT NOT NULL IDENTITY`; `oracle`: `NUMBER(19) GENERATED BY DEFAULT AS IDENTITY`.

## numeric: Decimales de precisión fija

## enum: Enumeraciones

```text
Column.enum(name: str, *enums: str, constraint_name: str | None=None, create_constraint: bool=False, native_enum: bool=True, length: int | None=None, validate_strings: bool=False) -> Enum
Enum(*enums: str, name: str | None=None, create_constraint: bool=False, native_enum: bool=True, length: int | None=None, validate_strings: bool=False)
```
Estados de un conjunto cerrado de strings no vacíos. Sin valores o con valores inválidos lanza `ValueError`. native_enum=True solicita ENUM nativo; en PostgreSQL asígnale constraint_name (name en el constructor). native_enum=False utiliza VARCHAR; create_constraint=True añade CHECK donde procede. validate_strings valida valores en el procesador del tipo, no crea un esquema HTTP.

```python
from orionis.database.schema.blueprint import Blueprint
from orionis.orm import Enum


table = Blueprint()
column = table.enum("status", "draft", "published", constraint_name="article_status", native_enum=False, create_constraint=True, validate_strings=True)
model_column = Enum("draft", "published", name="article_status", native_enum=False, create_constraint=True, validate_strings=True)
```

La factoría devuelve `Enum`; el constructor devuelve una nueva instancia del mismo tipo. Ambos heredan `ColumnDefinition`.

DDL de la declaración de prueba: `sqlite`: `VARCHAR(9) NOT NULL`; `mysql`: `ENUM('draft','published') NOT NULL`; `pgsql`: `article_status NOT NULL`; `sqlserver`: `VARCHAR(9) NOT NULL`; `oracle`: `VARCHAR(9 CHAR) NOT NULL`.

Estos fragmentos usan draft/published y nombre article_status con native_enum=True predeterminado. El ejemplo de construcción selecciona deliberadamente emulación y validación.

## Aplicar una declaración completa

Los ejemplos anteriores separan construcción de ejecución. En una migración, el blueprint recoge las mismas definiciones y `Schema` las materializa al salir correctamente del contexto.

```python
from orionis.database import Migration
from orionis.support.facades import Schema


class CreateProducts(Migration):
    async def up(self) -> None:
        async with Schema.create("products") as table:
            table.id()
            table.string("name", 120)
            table.numeric("price", 12, 2).default(0)
            table.boolean("active").default(True)
            table.timestamps()

    async def down(self) -> None:
        await Schema.drop("products")
```
