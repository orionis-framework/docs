# Auditoría del manual de Orionis 1.9.0

La referencia de código es `v1.9.0` (`931f5fe9622ff054fbd583f5128ec1de59015182`, rama `1.x`). Coinciden el objeto Git, `pyproject.toml` y `orionis/metadata/framework.py::VERSION`. La base del manual es `55e810e0077ea501512f59f6b3f59e69c0254461`. Ambos árboles estaban limpios al iniciar y no se encontraron archivos AGENTS.md aplicables. Astro y Starlight publican el manual vigente en `src/content/docs/{en,es}`. El catálogo y el orden de navegación residen en `config/`. Este directorio de auditoría queda fuera de las colecciones de Astro.

Las rutas de evidencia parten de la raíz del framework. Las rutas de página parten de la colección de cada idioma. Los estados de revisión editorial son independientes de la cobertura de pruebas. Una prueba de importación o la mera presencia de un nombre en el texto no verifican todo el comportamiento de un módulo.

## Comprobaciones del sitio

En el estado inicial, Node 22.22.1 pasó `npm run docs:test` (28 pruebas), `npm run docs:validate` (3547 enlaces internos) y `npm run build` con su `postbuild` (452 páginas renderizadas verificadas). El Node 18.16.0 predeterminado en esta máquina falla al leer los atributos de importación JSON. Se usó el Node 22 ya instalado, tal como indica el README del sitio.

`check_examples.py` analiza los bloques Python en ambos idiomas, resuelve importaciones explícitas de Orionis y comprueba argumentos de llamadas directas cuya firma puede obtener. Usa el entorno Python de la versión objetivo, desde la raíz del manual:

```powershell
..\framework\.venv\Scripts\python.exe -B audit/1.9.0/check_examples.py ../framework
```

Los bloques de un controlador, un proveedor o una sesión asíncrona pueden necesitar contexto. El comprobador resuelve importaciones en el intérprete del framework y no ejecuta los cuerpos de los ejemplos. Las pruebas de comportamiento se identifican por separado.

En Python 3.14.6, pedir `inspect.signature(McpTestClient)` con el formato predeterminado produce `NameError` al evaluar la anotación `IContainer` de su constructor. La inspección con `annotation_format=annotationlib.Format.STRING` devuelve la firma y permite validar argumentos sin evaluar esa anotación. El lote de transportes documenta otro caso en `WebSocket.accept`.

### Discrepancias observables

- El docstring del constructor de `orionis/queues/manager.py::QueueManager` menciona campos no admitidos como causa de `TypeError`. Una clave pública adicional válida sobrevivió a la normalización de la configuración del worker y del driver sync. Los nombres inválidos y tipos incorrectos para campos declarados siguen sujetos a validación.

- `orionis/storage/entities/file_info.py::FileInfo` describe `checksum` como SHA-256. Los drivers Azure y GCS devuelven el MD5 guardado por el servicio si está disponible. S3 devuelve `None`. La tabla en `storage/files-and-directories.md` documenta el resultado de cada implementación.
- `orionis/queues/contracts/failed_repository.py::IFailedJobRepository` y `orionis/queues/failed/repository.py::DatabaseFailedJobRepository` usan `failed_id` y `failure_id` respectivamente para `find` y `forget`. También difieren las anotaciones de la excepción en `record` (`BaseException` y `Exception`). Las guías usan el identificador posicional.

### Cobertura y comprobaciones

El inventario de los seis paquetes incluye 229 archivos Python (5 de background, 22 de cache, 48 de database, 94 de orm, 30 de queues y 30 de storage), más tres declaraciones `.pyi`: `schema/blueprint.pyi`, `_model_queries.pyi` y `factories/fake.pyi`. Se contrastaron las guías existentes en 69 páginas por idioma, incluidas las seis páginas índice y los catálogos Faker. Se actualizaron 26 pares de páginas. Se conservaron las rutas.

- **Validación estática de ejemplos.** Por idioma, `ast.parse` aceptó 1.390 bloques marcados como Python. Una comprobación de sus `from orionis… import …` resolvió 199 pares módulo/símbolo distintos. Sobre llamadas directas a símbolos importados o a métodos de clase/estáticos identificables en el mismo bloque, `inspect.signature(...).bind(...)` aceptó 474 llamadas por idioma. Es una comprobación de argumentos y no ejecuta las acciones, cuerpos de controladores ni proveedores generados.
- **Compilación SQL local.** Las 36 declaraciones compilables del catálogo, incluido el atajo `id()`, coincidieron con los 180 fragmentos de DDL publicados para SQLite, MySQL, PostgreSQL, SQL Server y Oracle. Se usaron `Column`, `SQLCompiler(driver=...).compileCreateTable(...)` y el dialecto SQLAlchemy correspondiente. Los cuatro marcadores sin compilador se comprobaron como declaraciones Python. No se validó aceptación por servidores remotos.
- **Ejemplos ejecutados.** En cada idioma se ejecutaron las 40 declaraciones de columna y las aserciones de hora repetida en `cache/source-artifacts.md`. Las cifras corresponden al runner Reactor con el ciclo de vida de aplicación.

- **Límite de ejecución.** Se verificaron las rutas remotas mediante compilación o dobles de prueba. Quedan fuera de la ejecución en vivo los servidores SQL distintos de SQLite, Redis, Memcached y las cuentas S3, Azure y GCS.

### Reproduction and limits

Tests ran with Python 3.14.6 from the framework virtual environment in a temporary export of the verified tag. The export included the application, tests, templates and CI scripts. `orionis.__file__` resolved to the export. Each process used the export as working directory and `PYTHONPATH`, with `PYTHONDONTWRITEBYTECODE=1`. The test project used `.env.example` and a disposable local key. No credentials or databases from the working framework project were copied.

Run the following commands inside an equivalent disposable export. Each module suite runs in its own interpreter. The nine suites returned exit code 0. Counts in the table describe the suites, so repeated mentions of one suite are counted once.

```powershell
foreach ($area in 'console','encrypter','environment','hashing','localization','logging','mail','test','view') {
    python -B reactor test --start-dir="tests/$area" --verbosity=1 --fail-fast=0 --no-panel
    if ($LASTEXITCODE -ne 0) { throw "$area failed" }
}
python -B reactor clear:cache --help
python -B reactor make:facade audit_catalog --accessor app.catalog --contract orionis.encrypter.contracts.encrypter.IEncrypter
```

The facade command created `app/facades/audit_catalog.py` and `audit_catalog.pyi`. The latter contained typed `encrypt` and `decrypt` methods. A separate local probe round-tripped AES-128-GCM and AES-256-GCM tokens, decoded their four fields, checked key/IV/tag lengths and distinguished absent and null tags. Each language’s logging example with an explicit UTC resolver executed successfully. A local signature-index check compared each command’s declared arguments with the actual destination section in each locale. Template fragments and application examples outside the executed fixtures were reviewed statically. Host-specific deployment and delivery to a live mail server were outside these runs.

The `Cipher` enum and the standalone key generator retain CBC entries. Both application configuration and the concrete encrypter reject them. The encrypted payload decoder requires the `tag` field. A missing field fails envelope decoding with `ValueError`, while a null tag passes structure decoding and fails decryption with `RuntimeError`. These distinctions are recorded in the key and encryption guides.

For this batch, `npm run docs:validate` passed under Node 22.22.1 (both locales and 3,553 links at the time of the check). `npm run docs:test` passed all 28 tests. The default shell’s older Node 18.16.0 could not parse the import attributes in the existing navigation module. Running the unchanged scripts under the major version specified by `.github/workflows/deploy.yml` resolved that environment issue.
